[2026-06-23] launchd EIO 회피 + 봇 자체 스케줄러 통합

■ 문제
- 맥미니 launchd bootstrap 이 'Input/output error(5)' 로 계속 실패(원인 미상, SSH 도메인 의심).
- 그 와중에 옛 bridge.py 프로세스가 orphan 으로 폴링 중이어서 409 충돌 + 신코드 미반영.
- 조치: pkill -f bridge.py 로 정리 후 nohup 으로 신코드 1개만 기동(현재 정상).
- 핵심 결함: 감시기(monitor)/정기분석(analyze)은 launchd 스케줄에 의존 → launchd 불능이면 안 돎.
  → 사용자가 /watch 한 종목 알림이 실제로는 안 오는 상태였음.

■ 해결: bridge 가 직접 스케줄 구동 (launchd 분리)
- bridge.py 에 run_schedulers 추가. 폴링 루프가 직접:
    · monitor.py 를 600초마다 spawn (긴급 신호 + 관심종목 진입가 알림)
    · analyze.py 를 한국시간 08:00/20:30/22:00(±15분, 하루 1회) spawn
  → com.kakaostk.analyze/monitor launchd 작업 없이도 자동 동작. (있으면 중복되니 둘 중 하나만)
- 설정 monitor_interval_sec 로 감시 주기 조정 가능.

■ 운영 현황
- 봇 기동: nohup python3 bridge.py (터미널 닫혀도 유지, 단 재부팅 시엔 수동 재기동 필요).
- 재부팅 자동기동(launchd)은 EIO 해결 후 과제로 남김(현재는 nohup 으로 충분).
- 재시작 시 반드시 기존 프로세스 종료: pkill -f bridge.py 후 재기동(409 방지).

■ 다음에 할 것
- git pull → pkill -f bridge.py → nohup 재기동 → /watchlist 로 RELY 현재가 vs $19.8 확인.
- (선택) launchd EIO 근본해결: plist DOCTYPE 추가/SSH 여부/도메인 점검 후 재시도.
